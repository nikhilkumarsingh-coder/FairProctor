# Results on the labelled sample

5,000 sessions, 294 confirmed malpractice. Every number below is **out of fold**: each session was scored by a model trained on the other sittings (5-fold, grouped by sitting, so a collusion ring never straddles train and test). Data is synthetic, generated by `data/generate.py`; see README for what that does and does not prove.

## Done-when checklist

| Criterion | Result |
|---|---|
| Cut the review queue by at least half while surfacing every confirmed case | Out-of-fold ranking: all 294 confirmed cases are in the top 44.9% of sessions — a **55.1% cut** vs the old rules, which flag 100.0% of sessions. Stricter test, threshold set without seeing the fold: 45.3% queued, 99.66% recall (1 missed). |
| Every flag links to the moments that caused it | 100.0% of queued sessions have time-stamped moments; 100.0% have a written reason. |
| Usable score at one frame every 5 s | AUC 0.9915 (full video: 0.9918); every confirmed case still above the threshold (recall 100.0%); rank correlation with the full-video score 0.934. |
| Pre-check runs in a phone browser, plain-language fixes | `/precheck` — tested at 390 px wide; English and Hindi. |
| False-flag rate reported separately for low-bandwidth and normal | Low: 48.4%, normal: 45.3% (old rules at the same queue size: low 76.4%, normal 32.6%). |

## Top of the queue (what the judges weight most)

| First N sessions | Precision (ours) | Precision (old rules, ranked by flag rate) |

| 25 | 88.0% | 80.0% |

The **Review first** band holds the top 298 sessions at 90.3% precision. AUC 0.9918, average precision 0.9036.

## Fairness: honest sessions sent to review

| Group | Ours | Old rules, same queue size |
|---|---|---|
| Low bandwidth (1,666 honest) | 48.4% | 76.4% |
| Normal bandwidth (3,040 honest) | 45.3% | 32.6% |
| Phone | 46.4% | |
| Desktop | 46.4% | |

The old rules flag low-bandwidth candidates about twice as often because blurry, sparse video produces more "face not visible" and "looking away" frames. Our gap is a few points. The remaining gap comes from less video to clear a candidate, not from video counting against them: missing video is fixed to the honest baseline before scoring.

These rates are high in absolute terms because the queue is sized to catch *every* confirmed case. Reviewers should work the **Review first** band first: it holds 298 sessions (6.0% of all) and 91.5% of the confirmed cases.

## CPU cost

Model training: 10.5 s on 2 CPU cores. Scoring from features: 0.036 ms per session. Live scoring through the API (including comparing answers against the ~200 other candidates in the sitting): about 2 s per session.
